# CCProxy 统一项目管理设计

日期：2026-10-26
状态：已与用户确认

## 一句话

在“模型映射”左侧新增统一的“项目管理”页面，直接列出所有已发现项目，并通过 Claude
与 Codex 两个下拉框设置各自的项目默认模型。

## 用户界面

- 顶部导航顺序为“项目管理”“模型映射”“请求日志”“用量统计”“设置”。
- “项目管理”是主窗口页面，不打开独立子窗口。
- 页面直接展示自动发现的全部项目，并按规范化路径合并 Codex 与 Claude 来源。
- 配置中已有、但目录暂时离线的项目继续展示，并标记目录不可用。
- 表格列为：项目、Claude 默认模型、Codex 默认模型。
- 两个模型列使用下拉框，首项为“不设置（停止托管）”，其余选项来自当前有效的精确映射。
- 下拉选项以 `mappingId` 为值、以 `clientModel` 为显示文字，界面仍保持用户要求的
  模型名展示；候选只包含代理当前首条命中时实际会走到的精确映射。
- 选择模型后立即保存并同步；选择“不设置（停止托管）”立即移除该客户端绑定。
- 停止托管只删除 CCProxy 绑定，不删除或回滚项目配置中已经写入的顶层 `model`。页面的
  下拉框会变空，但不会声称客户端文件中的旧模型已被清除。
- 不提供“添加项目”“编辑”或单独的“删除”按钮。
- 可选提供“刷新项目”按钮，用于重新扫描客户端会话目录。
- 每行支持按项目路径搜索；同一路径的 Claude 与 Codex 设置互不影响。
- 目录离线时仍允许编辑或停止该行已有绑定；保存可以成功，并显示“目录不存在”的同步状态。
  这样用户不会因为项目暂时不可用而失去停止托管的入口。
- Claude 与 Codex 的同步状态分别显示在对应下拉框下方，不额外占用独立状态列。

## 现有入口调整

- 移除模型映射每一行操作列的“项目默认模型”图标及对应打开子窗口逻辑。
- 移除协议与映射参数驱动的项目子窗口入口。
- 保留底层按客户端、路径和映射保存的绑定结构，不迁移现有用户配置。

## 数据模型

继续使用 v6 的扁平绑定：

```json
{
  "id": "b_xxx",
  "path": "/absolute/project/path",
  "client": "codex",
  "mappingId": "m_xxx"
}
```

- `client=codex` 对应 `openai_responses` 协议。
- `client=claude` 对应 `anthropic` 协议。
- 同一 `(path, client)` 最多一条绑定。
- 模型值由绑定引用的精确映射 `clientModel` 决定。
- 选择“不设置”时删除对应 `(path, client)` 绑定；另一客户端绑定不变。

## 后端接口

新增统一接口：

| 命令 | 作用 |
|---|---|
| `get_project_models` | 返回候选模型、全部合并项目、各客户端当前模型与同步状态 |
| `refresh_project_models` | 重新扫描会话目录后返回同一视图 |
| `set_project_model` | 按项目路径、客户端和映射 ID 创建、更新或删除绑定 |

视图的候选结构为 `{ mappingId, model, invalid }` 列表。候选生成遵循与代理路由一致的
“启用协议中按映射顺序首条命中”规则：

- 仅输出精确映射；通配和兜底映射不直接作为候选。
- 若先前的启用映射会匹配同一个 `clientModel`，后续精确映射已被遮蔽，不输出为候选。
- 完全相同的 `clientModel` 只输出首条有效精确映射。
- 任何已有绑定的 `mappingId` 不在最终候选集合中时，都额外把该绑定作为原值选项返回并
  保持选中；这包括协议、映射或供应商停用，以及被前置通配或同名映射遮蔽的情况。
- 原值选项不可重新选择，但用户可以清除或切换到其他有效候选。`invalid` 与同步状态关联，
  不因映射仅被路由顺序遮蔽就自动标为失效。

`set_project_model(path, client, mappingId?)` 规则如下：

- `mappingId` 非空且存在于该客户端最终候选集合时，创建或更新该客户端绑定；仅“启用、
  精确且供应商有效”但已被前置映射遮蔽的条目仍然拒绝。
  不再按模型名重新查找映射；更新已有绑定时保留原绑定 `id`，避免同步状态关联丢失。
- `mappingId` 为空时删除该客户端绑定，即停止托管；另一客户端绑定不变。
- 映射不存在、不是精确映射、不可路由或客户端非法时返回可读错误，不修改配置。
- Claude 多项目解析到同一 `settings.local.json` 时拒绝新绑定，继续保持现有冲突保护。

路径授权规则：

- 主进程先对在线目录做 canonicalize；已有绑定目录离线时使用纯词法规范化路径回退。
- 新建绑定必须对应当前全局发现列表中的项目，不要求项目来源包含目标客户端；统一页面允许
  为任一已发现项目设置 Codex 或 Claude 默认模型。
- 已经存在但目录离线的绑定允许更新到另一个候选映射或停止托管，但不能新增另一客户端绑定。
- 目录不在全局发现列表且没有已有绑定时拒绝写入，避免该命令变成任意路径写入口。

## 视图组装

统一视图由两部分合并：

1. 后台缓存的 Codex/Claude 会话目录扫描结果。
2. `projectModelBindings` 中已保存但本次未发现的项目。

每个项目输出：

- 以规范化绝对路径派生的稳定显示 ID 与绝对路径。
- `codex`、`claude` 来源标记。
- 当前 Claude/Codex 模型名或空值。
- 目录是否存在。
- 两种客户端各自的同步状态与消息。
- Codex 项目是否受信任。

在线项目以 canonical path 合并，离线绑定以纯词法规范化路径作为合并回退。

映射、供应商或协议被禁用时，绑定继续保留；后端把它作为不可重新选择的原值候选返回，
下拉框显示映射当前的 `clientModel` 并给出“绑定失效”同步状态。映射被删除或改成通配符时，
继续沿用现有配置归一化规则丢弃对应绑定，本次不改持久化结构。

## 数据流

1. 启动时后台扫描一次 Codex/Claude 会话目录并缓存。
2. 用户打开“项目管理”时读取缓存；缓存未完成时等待首次扫描，不重复扫描。
3. 用户选择模型，前端调用 `set_project_model`。
4. 主进程在配置事务锁内更新绑定并落盘。
5. 配置副作用沿用现有幂等全量同步逻辑，并发送 `project-models-changed`。
6. 前端重新读取统一视图，展示最新模型和状态。

## 错误处理

- 读取失败显示页面 notice，不清空已显示数据。
- 保存失败恢复/重载后端状态，不乐观保留未落盘模型。
- 目录离线时保留该行已有绑定的下拉编辑与停止托管能力，并显示目录不可用状态。
- 单个客户端同步失败只影响对应单元格的状态，不阻止另一客户端设置。
- 操作期间只禁用正在保存或正在刷新的控件，按钮与下拉框给出 loading/disabled 状态。

## 非目标

- 不新增手动添加项目。
- 不提供隐藏、恢复、编辑或独立删除项目操作。
- 不同时维护旧映射行内项目管理入口。
- 不改变项目配置写入边界、备份、安全校验或现有全量同步触发规则。
- 不支持 OpenAI Chat 的项目默认模型。

## 测试与验收

- 统一视图合并自动发现项目、不同来源和离线已绑定项目。
- Claude/Codex 候选分别来自 `anthropic` 与 `openai_responses` 的精确映射。
- 设置模型创建正确客户端的扁平绑定并写入对应项目配置。
- 清除模型只删除对应客户端绑定，另一客户端绑定保留。
- “不设置（停止托管）”不删除客户端配置文件中已有的 `model`。
- 目录离线后仍可停止已有绑定；但不能为另一客户端新建离线绑定。
- 通过 `mappingId` 唯一定位映射，同名模型不会产生歧义。
- 同名 `clientModel` 候选只保留代理首条命中的有效映射，被前置通配或同名映射遮蔽的条目
  不显示为可选项。
- 任何已有绑定的映射不在最终候选中时，包括停用或被前置映射遮蔽，都作为不可重新选择的
  当前值显示，并可切换或清除。
- `set_project_model` 只接受最终候选集合里的 `mappingId`，直接调用命令也不能绕到被遮蔽映射。
- 更新已有绑定时保留原绑定 `id`。
- 非法客户端、未知映射、未发现路径和 Claude 冲突返回错误且不落盘。
- 映射变化后现有绑定继续同步新的 `clientModel`。
- 顶部“项目管理”位于“模型映射”左侧。
- 项目表格无添加、编辑、删除按钮，两个模型列直接可编辑。
- 模型映射行不再显示项目管理图标。
