# CCProxy 统一项目管理设计

日期：2026-10-26
状态：已与用户确认

## 一句话

在“模型映射”左侧新增统一的“项目管理”页面，直接列出所有已发现项目，并通过 Claude
与 Codex 两个下拉框设置各自的项目默认模型。

## 用户界面

- 顶部导航顺序为“项目管理”“模型映射”“请求日志”“用量统计”“设置”。
- “项目管理”是主窗口页面，不打开独立子窗口。
- 页面直接展示自动发现的全部项目，并按规范化路径合并 Codex 与 Claude 来源。
- 配置中已有、但目录暂时离线的项目继续展示，并标记目录不可用。
- 表格列为：项目、Claude 默认模型、Codex 默认模型、同步状态。
- 两个模型列使用下拉框，首项为“不设置”，其余选项来自当前有效的精确映射。
- 选择模型后立即保存并同步；选择“不设置”立即移除该客户端绑定。
- 不提供“添加项目”“编辑”或单独的“删除”按钮。
- 可选提供“刷新项目”按钮，用于重新扫描客户端会话目录。
- 每行支持按项目路径搜索；同一路径的 Claude 与 Codex 设置互不影响。

## 现有入口调整

- 移除模型映射每一行操作列的“项目默认模型”图标及对应打开子窗口逻辑。
- 移除协议与映射参数驱动的项目子窗口入口。
- 保留底层按客户端、路径和映射保存的绑定结构，不迁移现有用户配置。

## 数据模型

继续使用 v6 的扁平绑定：

```json
{
  "id": "b_xxx",
  "path": "/absolute/project/path",
  "client": "codex",
  "mappingId": "m_xxx"
}
```

- `client=codex` 对应 `openai_responses` 协议。
- `client=claude` 对应 `anthropic` 协议。
- 同一 `(path, client)` 最多一条绑定。
- 模型值由绑定引用的精确映射 `clientModel` 决定。
- 选择“不设置”时删除对应 `(path, client)` 绑定；另一客户端绑定不变。

## 后端接口

新增统一接口：

| 命令 | 作用 |
|---|---|
| `get_project_models` | 返回候选模型、全部合并项目、各客户端当前模型与同步状态 |
| `refresh_project_models` | 重新扫描会话目录后返回同一视图 |
| `set_project_model` | 按项目路径、客户端和模型名创建、更新或删除绑定 |

`set_project_model` 在对应协议中查找可路由且启用的精确映射：

- 模型非空且找到唯一映射时，创建或更新该客户端绑定。
- 模型为空时删除该客户端绑定。
- 模型不在候选中、映射重复或客户端非法时返回可读错误，不修改配置。
- Claude 多项目解析到同一 `settings.local.json` 时拒绝新绑定，继续保持现有冲突保护。

## 视图组装

统一视图由两部分合并：

1. 后台缓存的 Codex/Claude 会话目录扫描结果。
2. `projectModelBindings` 中已保存但本次未发现的项目。

每个项目输出：

- 稳定显示 ID 与绝对路径。
- `codex`、`claude` 来源标记。
- 当前 Claude/Codex 模型名或空值。
- 目录是否存在。
- 两种客户端各自的同步状态与消息。
- Codex 项目是否受信任。

当前绑定模型不要求同时出现在下拉候选中；映射暂时失效时仍显示原值并给出绑定失效状态，
避免用户打开页面后丢失已有选择。

## 数据流

1. 启动时后台扫描一次 Codex/Claude 会话目录并缓存。
2. 用户打开“项目管理”时读取缓存；缓存未完成时等待首次扫描，不重复扫描。
3. 用户选择模型，前端调用 `set_project_model`。
4. 主进程在配置事务锁内更新绑定并落盘。
5. 配置副作用只同步受影响的绑定，并发送 `project-models-changed`。
6. 前端重新读取统一视图，展示最新模型和状态。

## 错误处理

- 读取失败显示页面 notice，不清空已显示数据。
- 保存失败恢复/重载后端状态，不乐观保留未落盘模型。
- 目录离线时禁用该行两个下拉框。
- 单个客户端同步失败只影响对应单元格的状态，不阻止另一客户端设置。
- 操作期间只禁用正在保存或正在刷新的控件，按钮与下拉框给出 loading/disabled 状态。

## 非目标

- 不新增手动添加项目。
- 不提供隐藏、恢复、编辑或独立删除项目操作。
- 不同时维护旧映射行内项目管理入口。
- 不改变项目配置写入边界、备份、安全校验或同步触发规则。
- 不支持 OpenAI Chat 的项目默认模型。

## 测试与验收

- 统一视图合并自动发现项目、不同来源和离线已绑定项目。
- Claude/Codex 候选分别来自 `anthropic` 与 `openai_responses` 的精确映射。
- 设置模型创建正确客户端的扁平绑定并写入对应项目配置。
- 清除模型只删除对应客户端绑定，另一客户端绑定保留。
- 非法客户端、未知模型和 Claude 冲突返回错误且不落盘。
- 映射变化后现有绑定继续同步新的 `clientModel`。
- 顶部“项目管理”位于“模型映射”左侧。
- 项目表格无添加、编辑、删除按钮，两个模型列直接可编辑。
- 模型映射行不再显示项目管理图标。
